🐞 除錯記憶（踩過的坑，改程式前先看這）

資料來源端

  • TWSE ETFortune etfExcel：HTTP 200 ≠ 內容完整。帶 range 篩選參數的 URL 實測回 248 檔（漏 0050），無參數版 250 檔才完整（2026-11-23 已改無參數版）。防護雙保險：fetch_etf_meta.py 的核心 ETF 驟降 guard（缺 0050/006208/009816 或檔數-10% 視同抓取失敗走備援）＋ test_known_errors 的核心 ETF 存在性檢查。
  • 11-22 P0 教訓：抓取成功但內容缺大戶 → 連鎖（分類檔掉 0050 → stocks.json 降級 unverified → CI 紅燈）。任何「官方清單類」資料都應有核心項目存在性檢查。
  • 排程閘門曾是盲區：ci_qa_gate.sh 原只跑 qa_gate.py，test_known_errors.py（P0-1 分類一致性等 150+ 項）只在 push 後才跑 → 壞資料先上線、事後諸葛。2026-11-23 起排程 job 閘門已同級（兩者都跑）。
  • 基準日 vs 公告日（取錯會把不同持股日的快照併成同日）：群益 date2（date1=公告日）、國泰 preDateC、台新 NAV_DATE（PUB_DATE=公告日）、玉山/安聯 CNavDt（CPcfdate=公告日）、野村 CNavDtStr、聯博 basket asOfDate。全文：skill taiwan-etf-holdings/references/issuer-sources.md 附錄 A。
  • bot 挑戰偵測：野村等投信以 HTTP 200 回驗證圖（非 JSON）→ 用 PNG/JPEG/GIF magic bytes 辨識，否則誤報「程式壞掉」。
  • .NET 日期 /Date(ms)/ 必須 +8 時區解，否則少一天。
  • 雙層 JSON：中信 ETFHoldingWeight、第一金 WebAPI（{"d":"<JSON 字串>"}）都要 json.loads 兩次。
  • pandas 3.0：astype(str) 保留 NaN 為 float 字串——逐格轉換，別整欄轉。
  • SystemExit 陷阱：腳本用 sys.exit() 處理缺依賴時，呼叫端 except ImportError 捕不到（SystemExit 不繼承它）→ 要 except (ImportError, SystemExit)。
  • TWSE MIS 反向 API（mis.twse.com.tw/stock/data/all_etf.txt）需 Referer: …/etf_nav.jsp；單請求全市場淨值/折溢價，只給最新一筆 → 每日累積。
  • 資料中心 IP 封鎖：兆豐 403（本站與上游 nctuwanglin/active-etf 同結論）、摩根 Excel 端點 404（2026-11-22 起）、TWSE OpenAPI 部分端點回 Swagger UI 殼——境外 VPS 環境限制，本機/台灣出口可能正常。
  • HTML 解析（投信 PCF 頁）：凱基有兩份相同持股表只取第一份＋欄位必 strip（漏了掉近半持股）；永豐留 36 個空表格模板只掃第一、二表頭之間；第一金代號藏在渲染後表格的 td（非「股票代號：XXX」字面量）；兆豐 WebForms 要把 hidden 欄位整包原封帶回；台新只掃「股數」表頭之後（期貨表在前）。
  • 聯博：只取 holdings-section-equity 分段（期貨權重可達 16%）；ISIN 可自行合成＝TW000＋代號＋Luhn 檢查碼。

演算法端

  • 申贖分離（scale 校正）：ETF 被申購/贖回時全部持股等比例增減——那是資金流不是換股。scale＝共同持股股數比值的真中位數（偶數取左右平均；取右側會漏判，上游歷史真踩過）；雙門檻：校正後股數 ≥5% 且 權重 ≥0.1pp；common<3 或 scale 超界 [0.2,5] → quality=insufficient_scale，校正欄位歸 null 寧缺勿假。
  • 缺股數不假造：無股數的來源退回純權重比對，UI 必須明示「無法分離申購贖回」。

⚠️ 開發注意事件（架構與約定）

  • CI 結構：每個排程班只跑一個 job（分時 cron，避免互搶）——「一班只有一個 job、其餘 skipped」是設計不是漏跑。閘門：scripts/ci_qa_gate.sh（qa_gate.py＋test_known_errors.py），錯誤即中止不推送。
  • stocks.json 體積預算 1,300KB：緊湊格式、無孤兒欄位（有防回歸測試）。不把 SQLite/大 JSON 塞進 git。
  • 歷史累積設計：ETP 持股歷史＝data/etf-holdings-history/*.tsv（六欄：record_date/etf_code/stock_code/stock_name/weight/shares，record_date+etf_code+stock_code 唯一去重冪等）；ETF 淨值歷史＝data/etf-nav-history/*.csv。items 第 4 欄＝股數（缺則 null，前端退回權重比對）。
  • stale carry：單檔抓取失敗保留舊資料標 stale；來源回舊（asof 較舊）不覆蓋較新資料。
  • 主動式 ETF 採集：fetch_etf_holdings_active.py 13 家投信 adapter；每日工作流自動跑（含 --only 重試失敗清單、冪等）；第一金 fundID 快取在 data/raw/firstsec-fundids.json。
